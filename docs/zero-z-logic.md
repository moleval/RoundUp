# Обнуление координаты Z — логика команды ОБНУЛИТЬЗЕТ

Статус: **реализовано**, модуль `ZeroZ.LSP`, редакция 1.
Команды: `ОБНУЛИТЬЗЕТ` / `ZEROZ`, самопроверка `ОБНУЛИТЬЗЕТТЕСТ` / `ZEROZTEST`.
Кодировка файла — CP1251 без BOM, префикс функций `zz-`.

---

## 1. Что делает команда

Приводит объекты чертежа в плоскость Z = 0: у объектов модели и всех листов
обнуляются координаты Z определяющих точек. Объект не сдвигается по X и Y.

Команда без диалога и без выбора: запустил — обработала модель и все листы — вывела отчёт таблицами.

Это **не** «плоское отображение» (FLATTEN из Express Tools): наклонная геометрия не
проецируется, а у объектов с несколькими точками (линия, 3D-полилиния, сплайн) все точки
приводятся к Z = 0, то есть объект становится плоским.

## 2. Принятые решения

| Вопрос | Решение |
|---|---|
| Внутрь определений блоков | **не заходим**. У вставки обнуляется только её точка вставки; геометрия и параметры внутри определения не меняются |
| Динамические блоки | обрабатываются как обычные вставки — меняется только точка вставки, параметры и определение не трогаются |
| Размеры | **обрабатываются**: сдвиг всей конструкции на -Z через ActiveX сохраняет ассоциативность и определение размера |
| Область обработки | модель **и все листы** — одна команда, отдельный вариант «только модель» не нужен |

## 3. Область обработки

Обход идёт по коллекции `Layouts`: каждый лист (включая `Model`) отдаёт свой блок
пространства, объекты перебираются `vlax-for` по этому блоку. Поэтому:

- обрабатываются и модель, и все листы, включая пустые (они просто дают нулевую строку в отчёте);
- определения блоков не попадают в обход вообще — это и есть требование «внутрь блоков не лезем»;
- xref-содержимое недоступно, а вставка xref обрабатывается как обычная вставка;
- замороженные и отключённые слои обрабатываются, заблокированные — пропускаются.

## 4. Две механики правки

### 4.1. Обнуление точек через entmod

Применяется к объектам, у которых положение задаётся набором точек: LINE, POINT, CIRCLE,
ARC, TEXT, ATTDEF, MTEXT, SOLID, TRACE, 3DFACE, SPLINE, RAY, XLINE, LEADER, IMAGE,
WIPEOUT, SHAPE, TOLERANCE, LWPOLYLINE, POLYLINE.

### 4.2. Сдвиг на -Z через ActiveX Move

Применяется к INSERT, HATCH, ACAD_TABLE, DIMENSION. Причина: у этих объектов одна опорная
точка, но есть связанные данные — атрибуты вставки, ассоциативный контур штриховки,
определение размера. `entmod` группы 10 передвинул бы объект, но:

- у вставки с атрибутами атрибуты остались бы на старой высоте (их координаты абсолютные);
- у ассоциативной штриховки разошлись бы контур и заливка;
- у размера разъехались бы определяющие точки в разных системах координат.

`vla-Move` двигает объект целиком вместе со связанными данными, поэтому для этих четырёх
типов используется он.

## 5. Главная ловушка: OCS и вектор 210

У CIRCLE, ARC, TEXT, INSERT, SOLID, 3DFACE, HATCH, IMAGE, SHAPE, TOLERANCE, ACAD_TABLE
координаты хранятся в объектной системе (OCS), задаваемой вектором выдавливания `210`.
Запись «z = 0» в группу 10 без пересчёта сдвигает объект по X/Y.

```lisp
;; OCS -> WCS, обнулить Z, вернуть в OCS того же объекта
(setq w (trans p ent 0))
(entmod (subst (cons 10 (trans (list (car w) (cadr w) 0.0) 0 ent))
               (assoc 10 ed) ed))
```

У LINE, MTEXT, SPLINE, ELLIPSE, LEADER, RAY, XLINE, POINT, DIMENSION координаты в WCS —
там Z обнуляется напрямую. `entget`/`entmod` не зависят от текущего UCS, поэтому команда
не трогает `UCS`.

Объекты с наклонным 210 (не (0,0,±1)) пропускаются: обнуление Z в их OCS не выводит объект
в плоскость Z = 0, а сброс 210 меняет его ориентацию в пространстве. Такие объекты видно
в отчёте отдельной строкой.

## 7. Алгоритм

```
1. Взять документ, коллекцию Layouts.
2. Открыть Undo-марку, поставить обработчик *error*.
3. Для каждого листа: собрать объекты его блока в список
   (сбор отдельным проходом, чтобы не править коллекцию во время обхода).
4. Для каждого объекта:
   а) тип не поддержан -> пропуск, счётчик «тип»;
   б) слой заблокирован -> пропуск, счётчик «слой»;
   в) 210 наклонный -> пропуск, счётчик «наклон»;
   г) INSERT / HATCH / ACAD_TABLE / DIMENSION -> сдвиг Move на -Z;
   д) простые типы -> обнуление точек через entmod;
   е) полилинии -> высота и вершины;
   ж) всё уже в допуске 1e-9 -> счётчик «уже 0», entmod не вызывается.
5. Закрыть Undo-марку, один REGEN на весь чертёж.
6. Вывести отчёт: сводка, таблица по пространствам, таблица по типам.
```

## 8. Защита

| Требование | Реализация |
|---|---|
| Одна операция UNDO | `vla-StartUndoMark` / `vla-EndUndoMark` вокруг всего прохода |
| Отмена (`Esc`) | `*error*` закрывает Undo-марку, печатает сообщение на русском |
| Ошибки `entmod` / `Move` | каждый вызов под `vl-catch-all-apply`, ошибка не прерывает проход |
| Системные переменные | команда **не меняет ни одной** — восстанавливать нечего |
| Заблокированные слои | не разблокируются молча, пропускаются с отчётом |
| Повторный запуск | идемпотентен: второй прогон даёт «Изменено 0» |
| Отладочный вывод | отсутствует |

## 11. Критерий готовности

## 12. Ограничения редакции 1

- Наклонные объекты (210 не (0,0,±1)) не обрабатываются — нужен отдельный режим «сплющить», это меняет геометрию.
- Внутрь определений блоков команда не заходит по решению заказчика: если внутри блока геометрия
  лежит в Z ≠ 0, вставка окажется в плоскости 0, но содержимое блока останется смещённым.
- Объекты на заблокированных слоях пропускаются; разблокировка — сознательное действие пользователя.
